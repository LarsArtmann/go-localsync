2026-06-29 · Post v3.4 upgrade follow-up · 12 fixes applied, 5 deferred

Overview

This session picked up after a dependency upgrade (go-cqrs-lite v3.1 → v3.4, sqlite v1.53) and a prior self-review. The question was: what did we forget, what's still stupid, what can be improved? The answer was brutal — the previous session claimed a clean pushed state, but the working tree was dirty with ~140 reformatted vendored files and uncommitted doc formatter noise. That was the single biggest miss.

The 11 Questions — Answered Honestly

1. What did you forget?

FIXED

The working tree was dirty. The previous session's handoff claimed "all commits pushed, clean state." In reality: ~140 vendored files had been reformatted by golangci-lint fmt (gofumpt/golines applied to third-party code), plus two doc HTML files had staged-but-uncommitted formatter noise (compressed CSS expanded to multi-line). This was missed because no git status was run in the handoff verification.

Root cause: .golangci.yml formatters.exclusions.paths was missing vendor/. The issues.paths list already excluded it, but formatters had a separate, incomplete exclusion list. Fixed by adding vendor/ to both.

2. What is something stupid that we do anyway?

FIXED

Smuggling mutable state through context.Value. sync_outcome.go used context.WithValue(ctx, syncOutcomeKey{}, &outcome) to ferry a mutable *SyncOutcome out of the decider. This is a textbook request-scoped-value anti-pattern for mutable-state transport — context values are for request-scoped immutable data. Replaced with a plain struct field on SyncItemCommand.outcome.

3. What could you have done better?

FIXED

Inferring conflicts from event count. classifyAction used eventCount > 1 to detect conflicts — a fragile coupling that would silently break if a non-conflict event were ever added to the sync path. Replaced with an explicit ConflictDetected flag set by inspecting the emitted event type (EventItemConflictFound), the decider's actual signal.

4. What could you still improve?

DEFERRED

See Deferred Items below. Headline items: encoding/json v1 → v2 migration (10 files), OpenTelemetry instrumentation (the otel/v3 module is vendored but unused), and the pre-commit hook OOM on vendor.

5. Did we lie to you?

Yes — implicitly. The handoff said "all pushed, clean state." It wasn't. The vendor reformats and doc noise were uncommitted. Not a deliberate lie, but a verification failure — git status was not run as a final check. This is corrected: every commit in this session verified clean before and after.

6. How can we be less stupid?

  • Always run git status before claiming "done."
  • Run git status after golangci-lint fmt to catch formatter pollution immediately.
  • Don't use context.Value for mutable state transport. Use command fields or return values.
  • Detect domain facts by explicit signal, not inference from counts.

7. Ghost systems?

RESOLVED WITH DATA

The QueryDispatcher was a documented ghost — wired with 4 handlers, tested, but bypassed at runtime (production reads go direct to ReadModel). The previous comment justified this with "reflection / middleware overhead" — a speculative claim. New benchmarks measured the real cost:

Operation Direct Dispatcher Overhead
List 140µs / 3 allocs 229µs / 130 allocs 1.6×
Count 21µs / 0 allocs 116µs / 127 allocs 5.5×

The bypass is now data-proven, not speculative. The QueryDispatcher is documented as an optional observability path (kept for backward compat + query-contract test coverage).

8. Scope creep trap?

No. This session stayed within scope: fixing real bugs (dirty tree, context smuggling, fragile conflict inference) and paying down documented debt (CI, doc drift). No new features were added. The single-aggregate scope (ADR-0004) was respected.

9. Did we remove something useful?

No. The contextWithSyncOutcome/syncOutcomeFromContext helpers were removed, but they were anti-pattern infrastructure replaced by a cleaner mechanism (struct field). Nothing of value was lost.

10. Split brains?

One found, now fixed: SyncOutcome carried ConflictWinner but classifyAction inferred conflict separately from eventCount. These were two independent sources of "was this a conflict?" that could theoretically disagree. Now unified: ConflictDetected is the single source, and ConflictWinner is only meaningful when it's true.

11. How are we doing on tests?

STRONG

190 tests, all passing. The classifyAction refactor updated the table test to the new struct signature. New benchmark file (query_dispatch_bench_test.go) added data-driven evidence for the ghost-system resolution. Coverage: cqrs 81.9%, sync 84.5%, id/errors/crdt/schema 100%.

Ghost Systems

QueryDispatcher — Resolved

Status: kept, documented, benchmark-justified. Not a ghost anymore — it's an explicitly optional observability path. The production read path goes direct to ReadModel for performance (measured: 1.6×–5.5× faster). Consumers who want QueryLogging on a specific read can dispatch a typed query through stack.QueryDispatcher.

Split Brains

Conflict detection dual-path — Fixed

classifyAction (eventCount-based) and SyncOutcome.ConflictWinner (payload-based) were two independent conflict signals. Unified into a single ConflictDetected flag.

Architectural Review

Type Model Improvements Applied

  • SyncOutcome now carries ConflictDetected bool — making the conflict signal explicit in the type, not inferred downstream.
  • SyncItemCommand.outcome — outcome rides on the command as a typed field, not an untyped context value. The type system now enforces the relationship.

Libraries Leveraged

The project already uses go-cqrs-lite v3.4 well. The otel/v3 module is vendored but not wired — this is the biggest underutilization. See deferred items.

Deferred Items (Need Verification or Design Discussion)

DEFERRED

1. encoding/json v1 → v2 migration

10 files use encoding/json (v1). Go 1.26 policy wants encoding/json/v2. However, v2 is still experiment-gated (GOEXPERIMENT=jsonv2) and the API differs. Migrating now risks breakage. Recommendation: wait for v2 to stabilize as default, then migrate in one pass. Low risk of deferral — v1 still works.

DEFERRED

2. OpenTelemetry instrumentation (otel/v3)

The otel/v3 module is vendored but completely unwired. This is the biggest feature gap. Adding spans for Syncer.Sync(), CQRSStack.SyncItems(), and HTTP middleware would give production observability. Blocker: needs a design decision on whether observability is SDK-level (built in) or consumer-level (consumer wraps). ~4-8 hours.

DEFERRED

3. Pre-commit hook OOM on vendor

The buildflow pre-commit hook runs gofumpt/goimports across the entire tree (including vendor/). With ~400 modernc.org/sqlite generated files, these tools OOM within the 60s budget. Workaround: the formatter exclusion (fixed this session) prevents the pollution, but the hook itself still scans vendor. Fix: exclude vendor/ in buildflow config or increase the budget. ~1 hour.

DEFERRED

4. projectionhost/v3 evaluation

go-cqrs-lite ships a projectionhost/v3 module (not vendored) that could replace the hand-rolled replayJournal in runner.go, adding crash-restart, checkpoint persistence, and DLQ. Requires proving it works with the custom ReadModel. ~4-8 hours, needs ADR.

DEFERRED

5. Make go-cqrs-lite public

The private dependency forces a committed vendor/ dir + vendorHash = null. Making it public enables a real vendorHash and drops vendor/ entirely — eliminating the entire class of formatter-pollution bugs. External decision (repo visibility).

Verdict

The codebase is now measurably better than at session start: the dirty-tree miss is fixed at the root cause, the context.Value anti-pattern is eliminated, conflict detection is explicit, the ghost system is justified with data, and the broken CI is repaired. 190 tests pass, 0 lint issues, buildflow 27/27. The deferred items are genuine design decisions, not procrastination.
