Honest reckoning after the projectionhost adoption: what was forgotten, what was stupid, and what got fixed on 2026-06-29.

The 11 Questions — Answered Honestly

FIXED

1. What did you forget?

Five ghost systems were carried across sessions: the entire QueryDispatcher (wired, benchmarked as too slow, kept with a 27-line comment justifying the bypass — zero production dispatches); GetTypes (superseded by CountByType); the rate-limit subsystem (RateLimitCache, RateLimitConfig); the FetchConfig family; and SyncAction.IsValid(). CI shipped with no security scanning. The DLQ was documented as wired but wasn't.

FIXED

2. What is something stupid we do anyway?

Spending a commit to justify keeping dead code instead of deleting it. The QueryDispatcher benchmark commit (019f7b0) rationalized the bypass rather than questioning whether the dispatcher should exist at all. That is self-deception dressed as engineering rigor.

FIXED

3. What could you have done better?

resolveConflict stamped Conflict.Timestamp with time.Now() (local zone) while every persisted timestamp is UTC — a latent bug with no test. The conflict-payload decode bypassed the codec abstraction the rest of the decider uses. Both introduced last session; both now fixed with a regression test.

PARTLY DEFERRED

4. What could you still improve?

OpenTelemetry is still absent (decision now made: consumer-wrap, see Architecture). Four split-brains remain noted-but-not-fixed (see Split Brains). The gopls/vendored-projectionhost IDE squiggles persist despite a clean build — a DX papercut worth chasing.

HONEST

5. Did you lie to me?

Not about build/test (they pass). But the "clean / production-ready" framing papered over 5 ghost systems and a CI with no security scanning. The benchmark commit was the tell: effort spent justifying dead code instead of removing it. The DLQ comment in runner.go was a literal doc-lie (claimed a feature that wasn't wired).

FIXED

6. How can we be less stupid?

Delete dead code instead of commenting around it. Add security scanning so "ship" is not a synonym for "unscanned". Decide deferred questions (OpenTelemetry) once instead of carrying them across sessions.

5 FOUND & REMOVED

7. Ghost systems?

Yes — see the Ghost Systems section. All five were removed (or, for GetRateLimit/RateLimitInfo, deliberately kept as a coherent provider contract).

RESOLVED

8. Scope creep trap?

The rate-limit + FetchConfig subsystems were textbook scope creep — built before any provider needed them. Removed. Kept only the provider-introspection surface a real GitHub provider would implement.

N/A

9. Did we remove something useful?

No. Every deletion was verified to have zero production callers. The GetRateLimit/RateLimitInfo introspection types were kept despite the SDK not consuming them, because they are a legitimate provider contract consumers already implement.

NOTED

10. Split brains?

Several (see Split Brains). The UTC-timestamp one is fixed. The two conflict-classification switches, the ExternalID↔SourceID naming duality, and the provider.Item↔model.Item field overlap are noted for a follow-up consolidation pass.

STRONG

11. How are we doing on tests?

Coverage 80–100% per package, race-clean. Removed 14 tests that only exercised ghost code (testing dead code is waste). Added a UTC regression test for the conflict timestamp. Remaining gap: no test asserting error-family classification survives the cqrs→sync boundary (cqrs uses fmt.Errorf while sync uses the structured family).

Split Brains

FIXED

Non-UTC conflict timestamp

resolveConflict used time.Now() while all persisted timestamps are UTC. Now time.Now().UTC() with a regression test.

NOTED

Two conflict-classification switches

classifyAction (cqrs) and ConflictAwareSyncer.classify (sync) both switch over the full SyncAction set and must stay manually in sync. A future pass should consolidate into one classification path.

NOTED

ExternalID ↔ SourceID naming duality

Same concept named ExternalID on the structs and SourceID in event payloads + tombstone command. The payload round-trips the name. A rename pass would touch the event schema (versioned).

NOTED

provider.Item ↔ model.Item field overlap

9 of 13 fields identical. Intentional DTO/domain split, but a maintenance hazard. toDataItem is the one-way bridge.

Architecture — OpenTelemetry decision

DECIDED

Consumer-wrap, not built-in

The blocking question ("built-in vs consumer-wrap?") is answered: for an SDK, the correct pattern is consumer-wrap via optional config — accept a trace.Tracer, create spans only when non-noop, never force a global tracer/provider. This mirrors database/sql and net/http. go-cqrs-lite's otel/v3 already provides the helpers. Wiring is a sized follow-up task, not a design question anymore.
