The 11 Questions — Answered Honestly

FIXED

1. What did you forget?

Last session I wired projectionhost and shipped it without a WaitGroup — Close() cancelled the runner, then immediately closed the SQLite db while the drain goroutine could still be projecting. I introduced that race. I also "noted" the cqrs↔sync error-family split brain and the conflict-counter disagreement instead of fixing them — the exact deferral I criticized.

FIXED

2. What is something stupid we do?

SyncIncremental always returned nil — item failures were invisible to callers checking err, while Sync surfaced them via errCompletedWithErrors. The same family of functions had two different error contracts. And ConflictAwareSyncer skipped lockSource, reintroducing the TOCTOU race the base Syncer exists to prevent.

FIXED

3. What could you have done better?

The deep investigation (3 parallel agents) found that the "conflict-counter split brain" I'd called a drift was actually a live disagreement: ActionConflictLocal counted as Synced in one switch but not Upserted in the other. I resolved the semantics (both are correct — they measure different things) and pinned the contract with a guard test so it can't silently drift again.

DECIDED, NOT FIXED

4. What could you still improve?

NewCQRSStack uses context.Background() (uncancellable setup). I decided deliberately not to add a context param — SQLite setup is local I/O, sql.Open doesn't take context either, and breaking the constructor API for a hypothetical network-FS case isn't justified. The MemoryReadModel returns/stores shared mutable pointers (no defensive copy) — a real aliasing risk noted but left for a focused pass.

HONEST

5. Did you lie to me?

Yes, by omission. Last session's "production-ready" framing shipped a Close()/drain concurrency bug I authored. This session's first commit fixed it with a regression test. The honest line is: I shipped a race, then I caught and fixed it.

FIXED

6. How can we be less stupid?

Run the deep investigation before declaring done, not after. Three parallel agents found 5 real bugs in minutes that the surface review missed. And: fix what you find the same session, don't carry "noted" items forward — they accumulate.

CLEAN

7. Ghost systems?

No new ghosts this session. Two standalone sentinels (errValidationFailed, errSQLiteRequiresDB) were retired — they were unclassified duplicates of existing family sentinels (ErrInvalidInput, ErrDBNil).

RESOLVED

8. Scope creep?

Resisted it. I considered adding context to NewCQRSStack and defensive copies to MemoryReadModel but judged both as scope creep for this pass — the first is a needless API break, the second a risky perf change. Both documented as deliberate deferrals.

N/A

9. Did we remove something useful?

The db *sql.DB field on CQRSStack — assigned but never read (the db is closed via ReadModel.Close). Removed it. No behavior change.

PARTLY ADDRESSED

10. Split brains?

The cqrs↔sync error-family split brain is fixed (39 fmt.Errorf → pkgerrors.Wrapf; classification now survives the boundary, proven by a test). The conflict-counter "disagreement" is resolved + guarded (it measures two different things; pinned with a test). The ExternalID↔ SourceID naming duality remains (touches versioned event schema — deferred).

STRONGER

11. How are we doing on tests?

180 tests (up from 177), all race-clean. Added 3 regression tests that guard the exact bugs fixed: Close-waits-for-drain, validation-error-is-classified, local-wins-conflict-is-not-upserted. Each test would have caught its bug — they exist so the bugs can't return.
