aFully Done

These are complete, tested, and production-ready.

+
CQRS architecture — no legacy CRUD Event-sourced via go-cqrs-lite v3: Decider, ReadModel, Projection, Stack. 3 domain events (ItemSynced, ItemConflictFound, ItemDeleted). Single authority for all state transitions.
+
Dual storage backends In-memory + SQLite (modernc.org/sqlite, no CGo) with identical ReadModel API, snapshots (EveryNEvents(10)), and correlation IDs.
+
Projection without a checkpoint store Synchronous live delivery via bus.SubscribeAll (watermill EventBus) + background replayJournal for SQLite catch-up. The idempotent projection tolerates replay/live overlap.
+
Pluggable CRDT conflict resolution CQRSConfig.ConflictResolver accepts any crdt.ConflictResolver[*model.Item]. LWWResolver is default; nil = remote-wins. Exported ConflictWinner constants + ParseConflictWinner.
+
Clear DTO/domain boundary provider.Item (DTO) ↔ model.Item (domain entity with SchemaVersion) via item_adapter.go. Decider, read model, events, and resolver all operate on *model.Item.
+
Sync engine Full + incremental sync, pagination, configurable rate limiting & retry, progress callbacks, conflict-aware sync, deterministic idempotent aggregate IDs.
+
HTTP API Huma v2 + stdlib adapter. 4 endpoints (GET /items, GET /stats, POST /sync, GET /health) with auto-generated OpenAPI 3 spec.
+
Pure-contract library Defines the contract only; no provider or CLI shipped in-repo. Reference GitHub provider + CLI lives in github-local-sync. Branded phantom-type IDs for compile-time safety.
+
Docs freshness pass (this session) Six core docs refreshed: AGENTS, FEATURES, README, ROADMAP, TODO_LIST, CHANGELOG (+ bonus CONTRIBUTING). Ghosts fixed, counts recomputed against code, README quick-start verified to compile.

bPartially Done

CI pipeline — test & lint pass, build & release do not

The test and lint jobs in .github/workflows/ci.yml pass. The build job (and the release job that depends on it) are broken because they target the deleted ./cmd/examples/github-sync path (now in github-local-sync). See Totally Fucked Up.

pkg/cqrs coverage at 81.4%

The largest and most important package has the lowest coverage. Error paths and some store-factory branches remain untested. The other 8 packages are 85–100%.

HTTP API — functional but unauthenticated

All four endpoints work and are tested, but there is no authentication, rate-limiting, or pagination-header middleware. Fine for local use; not safe on a network.

cNot Started

Deliberately out-of-scope so far — the contract-library boundary pushes some of these into consumer apps.

Observability

No OpenTelemetry instrumentation, metrics, or tracing. go-cqrs-lite v3 ships an otel/v3 module that is imported indirectly but not wired.

Data export

No JSON/CSV export of stored events. No -export equivalent.

Multi-user / multi-source sync

Read model does not track which user/source an event belongs to in a first-class way. Multi-source is supported at the provider level but not surfaced as a sync feature.

Daemon / scheduler / TUI

No cron/systemd integration, no watch mode, no Bubble Tea TUI. These are consumer-app concerns per the contract-library split.

Per-sync conflict-override

Conflict resolution is configurable via CQRSConfig.ConflictResolver but not per-sync (SyncOptions.ConflictResolver does not exist yet).

dTotally Fucked Up

Broken

CI build & release jobs reference deleted code

.github/workflows/ci.yml:96 (build) · ci.yml:104 (release)

The build job cross-compiles ./cmd/examples/github-sync, which was removed when the SDK became a pure contract library (the example moved to github-local-sync). go build on a deleted package fails, so the build job fails on every push and PR. The release job needs: [build], so tagged releases never run either. This is the single most damaging defect in the repo right now: no release has succeeded since the contract-library refactor.

Fix. Rework for a library-appropriate release flow: either (a) delete the build & release jobs (a pure module has no binary), or (b) move binary builds/releases into the github-local-sync consumer repo. Not fixed in this session because it is a design decision — flagged as high priority in TODO_LIST.md.
Tech debt

Committed vendor/ + vendorHash = null workaround

flake.nix · vendor/ · go.mod

go-cqrs-lite is private, so the nix sandbox cannot fetch it. The workaround is a committed vendor/ dir with vendorHash = null. It works, but it bloats the repo and forces manual GOWORK=off go mod vendor on every dep bump. The clean fix is to make go-cqrs-lite public.

eWhat We Should Improve

Fix the release flow first. Every other improvement is worthless if tagged releases keep silently failing. This unblocks all downstream consumers (including github-local-sync).
  • Make go-cqrs-lite public — drops vendor/, enables a real vendorHash, removes a recurring class of breakage.
  • Decouple living docs from session history — AGENTS.md must stay a context file, never a changelog. CHANGELOG.md now owns history; the session logs under docs/status/ are point-in-time archives.
  • OpenTelemetry — the otel/v3 module is already an indirect dep; wire spans for Syncer.Sync, CQRSStack.SyncItems, and HTTP middleware.
  • Harden the HTTP API — auth middleware, rate limiting, pagination headers, richer OpenAPI error schemas.
  • Adopt UpcasterRegistry — the schema.Version foundation in pkg/data/schema/ is ready for forward event migration; wire it.
  • Push pkg/cqrs coverage up from 81.4% — it is the largest package and the lowest-covered one.
