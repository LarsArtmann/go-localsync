# Status Report: EventID ULID Migration

**Date:** 2026-04-25 05:19 CEST
**Branch:** master (ahead of origin by 1 commit)
**Scope:** Two-repository change — `go-composable-business-types` + `go-localsync`

---

## Executive Summary

Changed `EventID` from `id.ID[EventBrand, int64]` (auto-incremented integer) to `id.ID[EventBrand, ulid.ULID]` (26-char time-sortable ULID). This required making the generic `ID[B, V]` type in `go-composable-business-types` support non-primitive value types by adding `encoding.TextMarshaler`/`TextUnmarshaler`/`BinaryMarshaler`/`BinaryUnmarshaler` fallbacks in all serialization methods.

**All tests pass across both repositories.** Full green suite: 80+ tests across 8 packages.

## d) TOTALLY FUCKED UP / RISKS

1. **`replace` directive in go.mod** — If committed as-is, CI will fail because `../go-composable-business-types` doesn't exist on CI. This is the #1 blocker for committing go-localsync.

2. **Migration 003 drops all data** — `003_ulid_pk.sql` drops the entire `events` table. Any existing user data is lost. Acceptable for a local-only tool, but worth documenting.

3. **`go.work` includes `go-cqrs-lite`** — The workspace file references `../go-cqrs-lite` which doesn't exist on disk. This means `go test ./...` (without `GOWORK=off`) fails. The workspace mode can't be used for testing.

4. **`Compare()` returns `ErrNotOrdered` for ULID** — The generic ID type can't express that `[16]byte` is sortable. Not a current issue since `Compare()` isn't used for `EventID`, but a known gap.

5. **Indirect dependency bumps** — `go mod tidy` bumped `golang.org/x/mod`, `golang.org/x/net`, `golang.org/x/sys`, `golang.org/x/text`, `golang.org/x/tools`, `mattn/go-isatty`. These are unrelated to the ULID change and will show up in the diff.

## e) WHAT WE SHOULD IMPROVE

1. **Uncommitted changes across repos** — Two repos with interdependent uncommitted changes is fragile. Should commit both atomically (g-c-b-t first, then g-localsync).
2. **go.work is broken** — References non-existent `go-cqrs-lite`. Should either create that repo or remove it from the workspace.
3. **Schema documentation drift** — AGENTS.md documents schema that no longer matches reality. Should update after migration changes land.
4. **No versioned migration tests** — Migration 003 isn't tested in isolation. `internal/database` tests only verify migration ordering and idempotency, not that individual migrations produce correct schemas.
5. **EventID in provider.Item** — The `provider.Item.ID` field uses `string` (the GitHub event ID), not `EventID`. The `EventID` is only generated at SQLite storage time in `toDBParams()`. This means the in-memory storage backend generates a new ULID on every upsert (no idempotency on ID field). The memory backend uses `GithubEventID` as the dedup key, so this works, but the `EventID` column is effectively unused for anything except being a PK.
6. **Test coverage gaps** — `pkg/errors`, `pkg/types` (non-EventID types), `pkg/testhelpers` have no tests. `cmd/examples/github-sync` has no tests.
